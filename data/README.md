# Synthetic data

Everything under this directory is generated by `make data` (`src/priorauth/data/generator.py`, fixed seed).
No real patient, note, identifier or provider is used. Do not edit these files by hand.

```
data/<split>/cases/<case_id>.json   what a system under test may read: request header + record pages
data/<split>/gold/<case_id>.json    ground truth, read only by the evaluation harness
data/test.sha256                    digest of data/test/ (frozen split, see below)
```

- **Splits.** `dev` is for iterating on prompts, rules and thresholds. `test` is never used for tuning.
- **Freeze.** `make data` refuses to write a `test` split whose digest differs from `data/test.sha256`.
  `tests/test_data.py` checks that the committed files are byte-for-byte what the generator produces.
- **Labels.** Each policy criterion is `MET`, `NOT_MET` or `INSUFFICIENT` (silent or self-contradictory record),
  with the exact quotes that justify it. The expected decision is `APPROVE` only when every criterion is `MET`
  and no page contains a prompt injection; otherwise `PEND`.
- **Traps.** `clean_approve`, `paraphrase`, `clean_pend`, `dose_x4`, `laterality_swap`, `date_conflict`,
  `contradiction`, `missing_evidence`, `injection`. Counts per split: `SPLIT_COUNTS` in the generator,
  enforced by `tests/test_data.py`.
- **Known coupling.** In `clean_pend` cases that target the MRI symptom duration (2 to 4 weeks of pain), the
  conservative-therapy criterion is also `NOT_MET`: six weeks of therapy cannot fit in a shorter history.
